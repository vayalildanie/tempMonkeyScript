# v1.5.5 Design: Remark Options Window Polish and Tech-Debt Pass

> **Status:** Proposed, not started. Plan: `PLANNING/plans/2026-10-31-v1.5.5-window-polish-and-tech-debt.md` (written for a Sonnet implementer).
> **Base:** `main` at `12837a9` (v1.5.4). Every finding below was read from that code or measured on the test fixtures in headless Chromium on 2026-10-31. Nothing has been checked on live NOVA.

## 1. Goals

1. **Window polish (the user's request).** The Remark Options header controls (⚙ Settings, Clear, ✕ Close) stay pinned to the window's top-right corner at every size the window can be resized to. Nothing in the window floats outside it, and extra height goes to something useful. v1.5.4's on-screen fitting (`fitPopover`, saved layout kept) is unchanged.
2. **Responsiveness and idle cost.** Stop the script from reacting to its own DOM writes, and end the QC page's endless idle re-render.
3. **Clean-up.** Remove the duplicated page-reading helpers that have already caused one bug (the QC row signature in v1.5.3), and clear small documentation and quote debts.

Out of scope: Histo_DB / Single-model Reference (v1.6), a build step or bundler, a framework rewrite, any change to which keys do what.

## 2. Window findings (measured)

The header is one flex row: title (`white-space: nowrap`), a spacer, the check badge (`nowrap`), then the three buttons. It cannot wrap or shrink, and its natural width is about 375px. The window can be resized down to `POPOVER_MIN_W = 300`, and `#rmd-popover` does not clip overflow.

| Window size | ⚙ (left–right, px from window's left) | Clear | ✕ | Result |
|---|---|---|---|---|
| 380 × 420 (default) | 246–278 | 284–337 | 343–374 | fits |
| 300 × 260 (minimum) | 246–278 | **284–337** | **343–374** | Clear and ✕ hang past the 300px edge |
| 700 × 700 | 560–591 | 597–650 | 656–687 | fits |

**This is the "floating" the user sees:** below about 380px wide, the controls overflow the window and render outside it. The comment on `POPOVER_MIN_W` says it "keeps the header buttons from crowding", but it is about 75px too small to do so.

Body, also measured:

- `#rmd-palette` has `max-height: 220px`. In a 700px-tall window the chips stop at 289px and the edit box at 371px, leaving about 300px of empty window below the "Likely" line.
- `#rmd-edit` is a fixed `height: 72px` with `resize: vertical`. That gives it a second, inner resize grip next to the window's own corner grip.
- At 260px tall, the palette is squeezed to 95px, about two chip rows.

## 3. Window design

### W-HEAD: controls pinned to the corner

- **Two groups.** The header becomes `[title …][badge][actions]`.
  - `.rmd-actions` wraps ⚙, Clear and ✕ with `flex: none` and never shrinks.
  - `.rmd-title` gets `min-width: 0; overflow: hidden; text-overflow: ellipsis` and is the first thing to give up space.
  - The badge sits directly left of the actions (v1.5.1 placement) with `flex: none`.
- **Compact steps,** driven by a container query on the window (`#rmd-popover { container-type: inline-size }`; Chromium 105+, which Tampermonkey on Chrome has):
  - Below 380px wide, the badge shows only its icon (🛡️/🚀/⭕). Its full text stays in `title`, and the label text is wrapped in a span that is hidden.
  - Below 340px wide, the title shows only 📝.
- **Minimum width.** Raise `POPOVER_MIN_W` to the width at which actions plus the compact badge plus 📝 fit, which should be about 280–300px. The implementer measures this and sets the constant to the measured value rounded up to 10. The resize code already reads the constant.
- **Backstop.** Add `overflow: hidden` to `#rmd-popover`, so a future header addition is clipped rather than floating. The resize handle is inside the window, so it is unaffected.
- **Invariant (the test):** for every width from the minimum to 900px, each control's distance from the window's right edge and top edge is the same as at the default width (±1px), and each control lies fully inside the window.

### W-BODY: height goes to the edit box

- `#rmd-palette`: remove `max-height: 220px` and use `flex: 0 1 auto; min-height: 64px; overflow: auto`. The palette takes its natural height when there is room and scrolls when there is not.
- `#rmd-edit-wrap`: `flex: 1 1 72px; min-height: 72px; display: flex`. `#rmd-edit` uses `height: 100%` (or `flex: 1`) with `resize: none`, so the window's corner grip is the only resize control. The backdrop `#rmd-edit-bg` already uses `inset: 0` and follows.
- The Likely and hint lines stay `flex: none` under the edit box.
- **Invariant (the test):** in a window taller than the content needs, the gap between the last visible child and the window's bottom edge is at most 24px, and the edit box is taller than 72px. At the minimum height, the palette is at least 64px and every header control and the edit box are visible.

### W-KEEP: what does not change

v1.5.4 behavior stays exactly as it is:

- `fitPopover`, `showPopover`, and the resize listener.
- The saved position and size are never overwritten by fitting.
- The re-create path.

The 7 tests in `tests/remark-window.spec.js` must stay green and unedited.

### What does not need fixing

**Shortcut speed.** There are no fixed sleeps on any key path. Every wait is `Utils.waitFor`, which polls once per animation frame and returns as soon as NOVA's cascader opens or accepts a value. So the time a score key takes is set by NOVA's own dropdown rendering, not by the script, and a refactor would not make the keys themselves meaningfully faster. The responsiveness gains available are:

- The highlight and badges coming back sooner after a re-render (D2, D8).
- No background CPU on QC rows (D1).
- Less work per typed character (D2, D7).

**Other ideas considered and rejected:**

- One shared MutationObserver for all modules. This is a larger change for a small gain once D2 filters own writes.
- Caching module lookups across settles. React replaces nodes, so the cache would need `isConnected` checks everywhere and is a bug risk for about 40-node scans.
- A bundler, so that `@require` loads one file. This adds a build step to a repo whose release today is just a push.

## 6. Risks

- **Container queries.** Container queries on a `position: fixed` element are fine in Chromium. Unknown on any non-Chromium browser the user might use; fallback is the full header, which still fits once `POPOVER_MIN_W` is raised.
- **P-SELF filtering misses a real NOVA change.** This could happen if NOVA re-renders inside an element the filter treats as ours. Filter only by our own root ids/classes, never by NOVA containers. The QC badges live inside NOVA modules, so filter by the record's target being inside `.qc-badge`, not by the module.
- **P-IDLE.** Write-if-changed must still re-add a badge that NOVA removed. Compare against the live DOM, not a cache.
- **Settle delay changes (D8)** are the only item that could change how the script behaves live under NOVA's real re-render timing. The plan's default is to centralize the constant without changing its value.
- **C-PANELFIT.** Generalizing `fitPopover` into `Utils.fitIntoView` touches the one panel (Remark Composer) that already works correctly; regression risk is covered by keeping the 7 existing `remark-window.spec.js` tests green (same W-KEEP invariant as section 3) plus new tests asserting QC Compare's panel now clamps the same way.
- **C-SEP** is a user-requested behavior change, not a bug fix — remarks written before this release keep whatever separator they already have (nothing rewrites old text); only newly-appended tokens use the new rule.

## 7. Separator simplification (C-SEP, user decision 2026-11-06)

**Current behavior** (`remark-composer.js` `separatorFor`): the box inspects its own trailing text to classify it as `'quote'` (ends in `"…"`, including the pre-v1.5.3 `Trans N "…"` form) or `'phrase'`, then picks a separator: quote→phrase joins with `": "`, phrase→phrase joins with `", "`, anything→quote joins with two spaces.

**Requested change:** drop the colon. A quote followed by a chip/phrase should join the same way a phrase followed by a chip/phrase does — with `", "` — while the existing comma behavior (phrase→phrase) and the quote-leading two-space rule are both kept exactly as they are.

**Design.** Because the colon was the *only* case where `prevKind` (what the box currently ends with) mattered — `newKind` (what's being appended) already fully determines the two-space rule — removing it collapses `separatorFor` to:

```js
function separatorFor(tail, newKind) {
  const t = tail.replace(/\s+$/, '');
  if (t === '') return '';
  if (newKind === 'quote') return '  ';
  return ', ';
}
```

`prevKind` and its detection regex (`/"[^"]*"$/`, including the comment calling out the pre-v1.5.3 `Trans N "…"` form it also had to match) are deleted entirely — not just the one branch. This is a direct, welcome side effect: D9's "known gap" comment and the dedicated `remark-writes.spec.js` test for "a chip is joined with ': ' when it follows a pre-v1.5.3 Trans N 'x' quote" both existed solely to carry that one branch; once the branch is gone, there is nothing pre-v1.5.3-specific left to special-case, because every join (regardless of what precedes it) now goes through the same `", "` rule.

**Test impact:** the three `separators` describe-block tests in `remark-writes.spec.js` need their expected strings updated (`": "` → `", "` where a quote is followed by a chip); the "follows a pre-v1.5.3 Trans N quote" test's title and assertion both simplify to the same `", "` expectation as the plain "follows a quote" case — it can be merged into that test (same assertion, no reason to keep it as a separate row) rather than kept as a distinct pre-v1.5.3 case.
