# v1.4.1 — Closed-state Check-Icon pills + quote-logic documentation

Status: approved by Danny, ready for implementation planning
Date: 2026-08-27

## Background

v1.4.0 (commit `05563cf`) split the userscript into `src/` modules, each
`@require`'d by the boot stub `annotation-scoring-shortcuts.user.js` from
`raw.githubusercontent.com/vayalildanie/tempMonkeyScript/main/src/...`. Local
edits are invisible to Tampermonkey until pushed to `main` — there is no
local test loop today (confirmed with Danny), so the release plan has to
account for a push-then-smoke-test cycle.

Modules involved:
- `src/remark-composer.js` (929 lines) — "Remark Options" in the UI. Owns
  the quote-insertion flow and the submit-check ("Check Icon") system.
- `src/scoring-shortcuts.js` (964 lines) — status panel with the
  pill-when-collapsed UI pattern we're reusing.
- `src/qc-compare.js` (1485 lines) — QC Compare panel, URL-gated to
  `/quality_` pages (line 1425), where `remark-composer.js` is explicitly
  disabled (line 910: `if (/\/quality_/.test(location.href)) return;`).

## Goals

1. Document where the quote-insertion logic lives (no behavior change).
2. Give Remark Options a closed-state pill, mirroring the
   `scoring-shortcuts.js` pill pattern, showing the current Check Icon.
3. Give QC Compare an equivalent pill in the same corner, shown only when
   its Legend is closed, displaying the same Check Icon state (read-only).

## Non-goals

- Fixing the quote-logic defects found during investigation (embedded `"`
  chars break the token, no double-quote guard, raw newlines in multi-line
  quotes). These are documented as known issues, not fixed here.
- Enabling Remark Options / Remark Composer to run on `/quality_` pages.
  The QC Compare pill is a read-only reflection of persisted state, not a
  live control.
- Making either new pill draggable or resizable. Fixed position only.

## Design

### 1. Quote-logic documentation (inline comments only)

Add short header comments, no separate doc file:

- `src/remark-composer.js:172` (`appendToken`) — comment noting it's the
  shared token-insertion primitive used by quoting, palette chips, etc.,
  and that it mirrors into NOVA's real Remarks textarea via
  `Utils.setNativeValue`.
- `src/remark-composer.js:400` (`tryQuoteSelection`) — comment describing
  the flow (grab selection → find enclosing `Trans N` module → build
  `Trans N "..."` token via `appendToken`) and three known defects, each
  one line:
  - selected text containing `"` is inserted unescaped and breaks the
    `Trans N "..."` token format (line ~425).
  - no guard against inserting the same quote twice on a repeat `Q` press.
  - multi-line selections retain raw newlines inside the token.

No parsing/formatting behavior changes — comments only.

### 2. Remark Options closed-state pill

New fixed-position pill in `src/remark-composer.js`, following the visual
idiom of `scoring-shortcuts.js`'s `#tl-score-pill` (lines 786-797:
`position:fixed; left:16px; bottom:58px`):

- New element, e.g. `#rmd-check-pill`, `position:fixed; left:16px;
  bottom:100px` — stacked directly above the existing score pill so the
  two never overlap regardless of which are visible at once.
- Visibility driven by the existing `active` flag (remark-composer.js:81):
  visible when `active === false`, hidden the moment the popover opens
  (`enter()`, line ~432) and re-shown on `exit()` (line ~461).
- Icon/label/color sourced from the same lookup `updateCheckBadge()` uses
  (remark-composer.js:748-760, keyed by `CHECK_MODES[checkModeIdx]`) so the
  pill and the in-popover badge never disagree.
- Click handler calls the same `enter()`/`toggle()` path used by the `O`
  key (remark-composer.js:841, `CFG.keyOpen`) — pill click and `O` keypress
  converge on one function, so there's exactly one way Remark Options
  actually opens.
- Refresh the pill's icon from `checkModeIdx` on `exit()` (line ~461), so
  a mode change made via `Z` while the popover was open is reflected the
  moment it closes.

No code changes needed in `scoring-shortcuts.js` for this — its line 753
legend text ("`O` Remark Options") remains accurate documentation of where
`O` is actually handled (remark-composer.js:841); there is no second `O`
handler to remove.

### 3. QC Compare closed-state pill

New fixed-position pill in `src/qc-compare.js`, same corner and offset as
the Remark Options pill for visual consistency (`left:16px; bottom:100px`
— QC Compare pages never load `remark-composer.js`'s pill, so there's no
literal DOM collision, but keeping the same coordinates keeps the pattern
recognizable across both contexts):

- Visibility driven by `helpOpen` (qc-compare.js:75, flipped at
  1400-1402): visible when `helpOpen === false`, hidden when the Legend is
  open. Wire the visibility update into `applyHelp()` (qc-compare.js:1266-1272)
  alongside the existing display/arrow toggling.
- Read-only: reads `localStorage.getItem('trans-tool:nova-score-check-v1')`
  (the `SCORE_CHECK_KEY` remark-composer.js already writes) each time it's
  shown/refreshed, maps the stored index through the same
  `CHECK_MODES`/icon table (duplicated as a small constant in qc-compare.js
  since remark-composer.js's module isn't loaded here), and renders the
  matching icon.
- Click is a no-op with a tooltip (`title="Check mode set on the
  annotation page"`) — there is nothing live to open on this page.
