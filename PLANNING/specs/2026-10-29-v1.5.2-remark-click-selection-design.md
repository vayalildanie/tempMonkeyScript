# v1.5.2 — Remark click selection and live synchronization

## Intent

Make the Remark Options popover easier to use alongside NOVA's own per-translation Remarks fields. While the popover is open, clicking a different eligible Remarks module selects it immediately and loads its current text into the popover. The annotator may keep typing directly into NOVA's textarea; those edits must appear in the popover as they happen. Edits in the popover continue to update only the selected NOVA field.

## Goals

- Click anywhere inside an eligible per-translation Remarks module to select its translation while Remark Options is open.
- Clicking the textarea selects and loads its content without preventing native focus, caret placement, or typing.
- Editing an eligible NOVA Remarks textarea directly makes that translation active and mirrors its current text into the popover on each `input` event.
- Preserve the existing arrow selector, target eligibility, row-change behavior, active-target highlight, and per-target isolation.
- Keep the behavior simple: the highlight, popover text, and NOVA field being edited always refer to the same target.

## Non-goals and safeguards

- Do not make source-translation text/title clicks select or quote a target; this behavior applies only to Remarks modules.
- Do not expand arrow navigation to translations excluded by the current `targetNumbers()` rules. In particular, an empty translation remains ineligible while populated translations exist; when none are populated, the current all-Remarks fallback remains.
- Do not prevent default click behavior, move focus to the popover, or intercept keystrokes in NOVA's textarea.
- No changes to scoring, QC Compare, `TransCursor`, Submit Check, quote routing, or the chip/settings UI.
- No broad refactor of target discovery/navigation. Reuse the existing cursor, target-change, and load-from-target paths; a small event-target helper is acceptable if it avoids duplicated module parsing/eligibility checks.

## Approaches considered

### A. Delegated events on `document` — chosen

Use delegated `click` and `input` handling, matching the existing document-level delegated input listener. Resolve the clicked/edited target through its closest `[data-module-name]`, parse it as a Remarks module, and accept it only when its translation number is in the current eligible target list. Route selection through `cursor.set()` and the existing `selectTarget()`/`loadProxy()` path. This is resilient to NOVA replacing module nodes and avoids changing the navigation model.

### B. Per-module listeners — not chosen

Attach listeners directly to each discovered Remarks element. This is small initially, but NOVA re-renders and replaces these nodes; listener rebinding would add lifecycle complexity and risk missed clicks or edits.

### C. Broader target-selection refactor — not chosen

Introduce a new abstraction for all keyboard and pointer selection. This could help if more selection sources are planned, but the existing cursor and `selectTarget()` already provide the necessary shared path. A wider refactor would increase regression surface without adding value for this feature.

## Behavior and constraints

- Mouse selection is enabled only while the Remark Options popover is open.
- A click anywhere within an eligible Remarks module selects that translation. Clicking its textarea retains native browser focus and caret behavior; the popover is updated without stealing focus.
- A direct `input` event from any eligible NOVA Remarks textarea selects that translation (if needed) and mirrors its current value into `#rmd-edit`. This supports typing, paste, and other normal input sources. The composer-to-NOVA synthetic input event must remain a no-op in the reverse direction when values already match.
- Switching targets reloads from the live NOVA textarea at switch time. Since composer edits already mirror immediately, target changes must not discard pending text or copy text to another translation.
- A click or direct edit that selects a target consumes the special first-ArrowUp jump, so subsequent arrow movement proceeds from the chosen target rather than unexpectedly jumping to Trans1.
- Delegation must survive React-style replacement of a module or textarea. Duplicate nested wrappers with the same translation number continue to resolve as one logical target.
- Closed-popover behavior remains unchanged: page-side input does not need to update the hidden proxy; opening continues to use the existing initial-target rule.

## Test and release expectations

Extend `tests/remark-targets.spec.js` with Playwright coverage for: clicking a non-textarea part of a Remarks module; clicking its textarea while preserving focus/caret; immediate loading of existing text; direct editing of a different eligible textarea and live mirroring; bidirectional writes staying on the correct translation across repeated switches; click/input behavior while closed; ignored ineligible empty translations; consuming the first-ArrowUp special case; same-target clicks; and selection/synchronization after React-style node replacement. Retain coverage for row changes, arrows, quotes, and target isolation, then run the full suite and JavaScript syntax checks.

For the eventual v1.5.2 implementation, update the userscript version markers and release documentation consistently. Do not claim live NOVA verification from fixture tests alone; explicitly list any live-only checks in the release notes.
