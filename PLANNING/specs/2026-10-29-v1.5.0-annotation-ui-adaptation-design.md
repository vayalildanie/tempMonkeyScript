## Intent

Adapt the userscript to the updated annotation page, where every translation
has its own Remarks field, while preserving the existing scoring workflow.
Add a repeatable browser-based test harness built from the supplied outerHTML
so future DOM/UI adaptations can be developed and verified without depending
on a live authenticated NOVA session. Module 4 / Single-model Reference
("Histo_DB") is no longer part of v1.5; it is deferred to planned v1.6.

All implementation changes are to be made in the isolated
`v1.5.0-ui-adaptation` worktree and integrated into the project only after the
work is reviewed. The README is out of scope until the user asks for it to be
updated.

## Current findings

- The supplied page has separate `TransN Remarks` modules alongside the
  existing `TransN Score` modules. The old single
  `[data-module-name="Remarks"]` target is absent, so Remark Composer's
  existing write/sync path has no destination on this UI.
- Trans2's Remarks module is named `Trans 2 Remarks`; the other sample names
  are `Trans1 Remarks`, `Trans3 Remarks`, etc. Its extra space must not make
  it invisible to discovery.
- Score and translation modules retain their `TransN` and `TransN Score`
  names. The sample includes Ant Design cascader structure and uses the
  existing `preview-content` translation text container.
- The sample's Trans4–Trans7 translation text is empty. Harness fixtures must
  populate those slots with clearly synthetic content to exercise the
  right-hand column and score/remark workflows.
- The capture is supplied as an external local file rather than checked into
  the worktree. The implementer must use the user's supplied
  `NOVA Annotate HTML example.txt` at
  `C:\Users\Admin\Documents\projects\NOVA\NOVA Annotate HTML example.txt`
  when extracting the fixture; if that file is unavailable in a later
  environment, the fixture provenance/details must be treated as unverified.
- `TransCursor` already encodes the required left/right column split
  (`leftMax: 3` in Scoring Shortcuts), but it receives its available numbers
  from Scoring Shortcuts' DOM discovery. Test the complete flow before
  changing the cursor implementation.
- `Utils.transNumFromModuleName()` currently expects `Trans` immediately
  followed by digits. A narrow optional-whitespace accommodation would cover
  the Trans2 Remarks spelling while preserving module suffix matching.
- QC Compare is URL-exclusive and should have no production-code changes.
  Shared utility changes, if any, must be regression-tested against the
  existing module-name and cursor contracts.

## Goals

1. Make scoring shortcuts navigate horizontally between scoreable Trans1–3
   and Trans4–7 controls on the updated page.
2. Verify `3` and `C` apply to the active Score selector and auto-advance;
   verify `2` opens label selection and that a terminal `1`–`9`/`0` label
   choice commits and advances to the next Score selector.
3. Restore and verify the Remark Composer safety submit check, including its
   Submit Check mode's synthetic Space submission, which is currently
   reported nonfunctional on the changed UI.
4. Preserve Scoring Shortcuts panel usability and appearance on the new
   layout.
5. Make Remark Composer target the active translation's own Remarks field,
   visibly identify that destination while open, and allow arrow-key
   selection among Remarks targets.
6. Show a live, informational list of translations likely to need remarks:
   score values `2 Points` or `Confusing`. A score of `3 Points` is not listed.
7. Ensure the Remark Composer can write to the currently highlighted
   translation's Remarks field, and that `Q` with no active text selection
   focuses the composer window/edit box. Broader button workflows are reserved
   for user feedback rather than exhaustive automated coverage.
8. Remove the old “Trans N” highlight behavior from the composer text overlay.
9. Add a small browser-based fixture/test harness for the submit checker,
   scoring shortcuts, focused Remark Composer behavior, and shared DOM
   utilities.

## Non-goals and safeguards

- No QC Compare feature/DOM behavior changes are planned.
- No Module 4 / Histo_DB database or Single-model Reference implementation
  is planned for v1.5.0; its target is v1.6 and it needs its own design pass.
- Do not automate every Remark Composer control in Playwright; prioritize
  target selection/write routing and the `Q` focus fallback, then gather
  broader interaction feedback from the user.
- No README edits during this work.
- Do not loosen or rewrite selectors broadly. Literal platform module names
  remain functional contracts; only the observed optional whitespace in
  `Trans 2 Remarks` is accommodated.
- Do not make `3 Points` remarks impossible: the list is a recommendation,
  not a restriction on navigation or writing.
- Do not change `TransCursor` unless a failing test demonstrates that its
  number-based column behavior is itself incorrect.
- Preserve current quote containment: selected text must be within one
  translation. Quote destination follows the confirmed decisions below.

## Approaches considered

### A. Playwright browser fixture (recommended)

Create a slim, checked-in HTML fixture derived from the supplied NOVA
outerHTML, with synthetic populated Trans4–Trans7 content and a small
Ant-cascader simulator. Run the real `src/*.js` modules in Playwright against
that fixture. Use browser layout, DOM events, keyboard events, selection and
`Range` behavior to test the actual userscript pathways. This is the best fit
for lateral movement, popup adjacency, visible highlighting, UI sizing and
quote-selection behavior. It adds a browser-test dependency and a small
fixture-maintenance obligation.

### B. DOM-only unit/smoke harness

Use Node with a lightweight fake DOM to test parsing and cursor logic, plus
module-construction smoke tests. This is faster and has fewer dependencies,
but cannot credibly test layout-sensitive popup matching, scroll behavior,
visible highlight placement, or browser Selection/Range quoting. It does not
meet the requested UI validation by itself.

### Recommendation

Use A, with plain JavaScript tests and Playwright to match the repository's
userscript language and to exercise real browser behavior. Keep pure
`TransCursor` checks alongside the browser tests where useful. The production
userscript remains plain files loaded by `@require`; tests do not add a build
step or bundle the shipped code.

## Proposed behavior

### Scoring Shortcuts

- Continue discovering score modules in Trans-number order and skipping
  translations with no text.
- Verify ←/→ toggles between the left (1–3) and right (4–7) columns and
  lands on the remembered slot in that column when scoreable, otherwise the
  first scoreable slot there. Both arrows retain the existing toggle behavior.
- Verify `3` and `C` commit and advance; verify `2` leaves its cascader open
  for label choice and does **not** advance until a leaf label is selected.
  A terminal numbered choice commits the label and advances. A category with
  further children remains in label mode as today.
- Exercise the panel on the three-column screenshot-derived layout. Assert
  it is visible, within the viewport, and its title, controls, legend and
  status do not overlap or clip at the normal fixture viewport. Capture a
  screenshot for review rather than relying only on pixel-golden tests.
- Evaluate `Utils.transNumFromModuleName()` with existing names and
  `Trans 2 Remarks`. If the shared parser is adjusted, retain its existing
  suffix semantics and add unit coverage; leave `TransCursor` unchanged
  unless integration testing exposes a cursor-specific failure.

### Submit safety check

- Test the three persisted modes: Label Check, Submit Check, and Check Off.
- Label Check blocks Enter when any populated translation is incomplete,
  allows the platform's normal Enter effect on a complete row, and does not
  synthesize Space. A mouse click on Submit remains an override.
- Submit Check blocks on an incomplete row. On a complete row, Enter is
  prevented as the initiating key and one synthetic Space keydown/keyup pair
  reaches the mock platform submit handler and produces exactly one submit.
  This end-to-end assertion is required because the reported failure is that
  Space no longer triggers the platform's submit behavior.
- Check Off leaves Enter untouched and emits no synthetic Space.
- `Z` cycles modes in the documented order and the choice survives reload.
- Cover empty-row auto-advance when Submit Check is active: after a row
  change to a row with no scoreable translations, the delayed Enter check must
  use the same clean-pass/synthetic-Space path once. Ensure a stale timer
  cannot submit after moving to another row or changing mode.
- Record the Space event target and properties in the fixture so dispatching
  an event without activating the submit path fails visibly.

### Remark Composer

- Discover per-translation Remarks fields by module name, parsing the
  translation number and selecting the contained textarea. Deduplicate
  nested outer/inner modules so each Trans number maps to one target.
- Make the active target explicit in module state. All composer-originated
  text writes and mirroring go to that target's React-controlled textarea,
  not to the removed global Remarks field. Re-query the live DOM when needed
  because NOVA may replace fields during React renders.
- While Remark Options is open, show an active-target highlight on the
  corresponding `TransN Remarks` module. Remove it on close and restore it
  after DOM replacement. Arrow keys move the target in Trans-number order,
  update the highlight/status, and bring the target into view.
- While the composer is open but focus is in the composer edit area or a
  settings input, preserve native caret/field arrow behavior. Arrow navigation
  applies when focus is not in a text-editing control; this prevents the
  composer from stealing arrows needed to edit remark text. The moved help
  text must make this focus-dependent navigation discoverable.
- Remove `highlightTransRefs`/`.rmd-tref` visual treatment of “Trans N”
  mentions from the composer backdrop. Keep the edit/backdrop text and caret
  alignment mechanism, without highlighting those references.
- Below the text box, render a live informational summary of likely-remark
  translations, read from current score values. Include only `2 Points` and
  `Confusing`; identify each by Trans number and score. Refresh on relevant
  page mutations and score changes. Empty/unscored and `3 Points` entries
  are omitted. The summary must not alter the target list or block writes.
- Keep `Q` quote selection constrained to one translation. If Remark Options
  is closed, opening it selects the first populated translation whose score
  does not begin with `3 Points`, falling back to Trans1 when none exists,
  then appends the quote to that target. If it is already open, keep the
  currently highlighted target and append there. A selection spanning
  translations is rejected. With no selection, focus the composer edit box.
- Remove title-click whole-translation references completely, including the
  clickable-title styling, document click handler, and all help text that
  describes clicking a title. `Q` is the only quote action.
- Move the existing composer help sentence from Remark Options to the bottom
  of Scoring Shortcuts. Rewrite it to describe arrow selection while focus is
  outside editable text, `Q` quoting, chip phrases, and `Z`/`Enter`. Do not
  mention title clicks or claim Scoring Shortcuts owns `Q`.
- The Scoring Shortcuts panel must remain compact and readable with the new
  help text; allow its existing wrapping/auto-height behavior to work rather
  than imposing a fixed height.

### Shared modules and QC regression boundary

- Candidate shared change: allow optional whitespace between `Trans` and
  its number in `Utils.transNumFromModuleName()` while preserving its suffix
  contract. This covers the actual `Trans 2 Remarks` name. Confirm with
  tests before changing it.
- `Utils.transHasText()` should continue reading translation content from
  `[data-module-name="TransN"]`; Remarks naming must not affect it.
- `TransCursor` remains number-based and UI-agnostic. Add tests for the
  existing left/right contract; production edits only if the full fixture
  proves the implementation itself fails.
- No QC Compare selectors, keyboard behavior, or rendering are to change.
  Tests should include shared-helper regression coverage. A QC live-page
  integration test is not possible from the supplied annotation HTML, so do
  not claim one.

## Test harness design

### Fixture

- Add a focused HTML fixture under `tests/fixtures/` based on the supplied
  outerHTML, retaining the real module nesting/classes/attributes needed by
  the selectors, score controls and per-translation Remarks fields.
- Replace/transcribe dynamic IDs and redact task-specific content as
  appropriate; document that fixture provenance is the user-supplied
  `NOVA Annotate HTML example.txt` capture.
- Populate Trans4–Trans7 `.preview-content` with synthetic, visibly marked
  text. Include rows/score states that provide both columns and targets for
  `3 Points`, `Confusing`, empty, and `2 Points` picker cases.
- Model an initially closed cascader and menus using the classes/attributes
  relied upon by production code (`.ant-select-selector`, input
  `aria-expanded`, `.ant-select-dropdown`, cascader menu items and
  `data-path-key`). The simulator should expose enough interactions to test
  root score selection, label categories, and terminal leaf selection without
  attempting to reproduce NOVA's full framework.
- Include a mock submit control and a platform-like event handler that
  responds to the same Space key event path as the live page. Count actual
  submit-handler activations separately from dispatched events; event
  dispatch alone is not proof that submission works.
- Include both `Trans2 Remarks` and the exact observed `Trans 2 Remarks`
  spelling in fixture coverage; the actual sample spelling is the latter.

### Test layers and acceptance scenarios

1. **Shared utility and cursor tests:** module-number parsing for all existing
   forms plus `Trans 2 Remarks`; text-present/empty detection; `TransCursor`
   column toggle, remembered positions, clamping, and `nextIn` behavior.
2. **Scoring integration tests:** with all seven synthetic translations
   populated, start on Trans1, move to Trans4 with either lateral arrow,
   return to the left column, and verify remembered-slot behavior. Confirm
   empty translations are skipped when a separate test fixture leaves one
   empty.
3. **Score/picker tests:** `3` and `C` set the selected Trans's actual
   cascader and advance. `2` opens the label flow without advancing; each
   numeric key `1`–`9`/`0` selects the corresponding item in the deepest
   menu, and a terminal item advances to the next score selector. Include a
   category-with-child case that does not advance early and read-back mismatch
   cases for both root score and label selection that stop rather than
   advancing. In particular, a failed leaf selection must not count the
  already-present `2 Points` value as confirmation of a completed label.
4. **Submit-check tests:** exercise Label Check / Submit Check / Check Off
   against incomplete and complete rows. Assert blocked Enter is prevented,
   expected normal Enter passes through, only Submit Check dispatches exactly
   one Space pair on a clean pass, and the fixture's actual submit handler
   runs exactly once. Test `Z` cycle/persistence, mouse-submit override, and
   delayed empty-row auto-advance including stale-timer cancellation.
5. **Scoring panel check:** inspect visibility, viewport bounds, key legends,
   status and skipped text; save a screenshot artifact at the fixture's
   desktop viewport for human review.
6. **Focused Remark Composer integration:** `O` selects the first populated
   translation whose score does not begin with `3 Points`, or Trans1 if none
   exists. Highlight that target. The first ArrowUp from that initial target
   jumps to Trans1; later arrow movement is sequential. Typing writes only to
   the highlighted target across target switches and React-style replacement.
   `Q` with no selection focuses `#rmd-edit` at the end. `Q` with a valid
   selection opens/targets as specified and appends the quote. Title clicks
   do nothing. Do not exhaustively automate every composer button; reserve
   broader usability review for user feedback.
7. **Likely-remark summary:** `2 Points` and `Confusing` appear; both bare
   `2 Points` and fully labeled `2 Points / …` count as likely-remark
   entries; `3 Points`, empty and unscored entries do not. Updating a score
   refreshes the summary, including child-list or text/value mutations, not
   only row changes.
8. **Text and selector regression checks:** no `.rmd-tref` highlight remains;
   no dependency on `[data-module-name="Remarks"]`; active-target arrows do
   not intercept caret movement in the composer or settings fields; and the
   moved help accurately describes focus-dependent arrows and contains no
   title-click instruction.
9. **Module smoke test:** load the same module files against a blank/minimal
   DOM and ensure Scoring Shortcuts, Remark Composer and QC Compare factories
   construct/start without throwing. Avoid asserting QC behavior against the
   annotation fixture.

### Test-first workflow

For each behavior change, first add the failing Playwright/unit scenario,
run it to establish the failure, then make the smallest production change,
and rerun the focused test. For the submit regression, run the new fixture
against the unmodified code first and record whether the platform-like Space
handler is activated; only then change production code. Because the capture
does not include NOVA's event-listener implementation and the test fixture can
only model it, a final manual smoke test on the live annotation page is also
required for Submit Check mode. Finish with the entire suite, syntax checks
for all shipped JavaScript files, and a review of the generated screenshot
and git diff. Tests should exercise user-visible paths through module
`start()`; avoid adding production test-only exports unless the harness proves
they are necessary.

## Confirmed decisions

1. **Initial target:** `O`, and `Q` when the composer is closed, selects the
   first populated translation in order whose displayed score does not begin
   with `3 Points`. This includes `2 Points`, fully labeled `2 Points / …`,
   `Confusing`, and empty/unscored translations. If every populated score
   begins with `3 Points`, select Trans1.
2. **First upward move:** from that initial target, the first ArrowUp jumps
   directly to Trans1. Subsequent arrow movement is sequential and clamped.
3. **Open-composer quote:** when the composer is already open, `Q` appends to
   the currently highlighted Remarks target rather than changing it.
4. **Title clicks:** remove the feature completely. Clicking a translation
   title must not insert text or change the selected target.
