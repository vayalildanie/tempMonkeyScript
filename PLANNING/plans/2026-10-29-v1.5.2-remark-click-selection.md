# v1.5.2 Remark Click Selection Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let an open Remark Options popover follow an eligible Remarks field selected or edited directly on the page, while preserving native textarea editing and existing arrow behavior.

**Architecture:** Keep all behavior in `src/remark-composer.js` and add one small target-resolution helper used by delegated `click` and `input` handlers. Route accepted selections through the existing `cursor.set()` / `selectTarget()` path, and reload the popover only when the translation changes. Do not split the file or refactor `TransCursor`; the existing interfaces already provide the required boundary.

**Tech Stack:** Plain JavaScript userscript modules, Playwright tests, and the existing reduced annotation fixture.

**Spec:** [PLANNING/specs/2026-10-29-v1.5.2-remark-click-selection-design.md](../specs/2026-10-29-v1.5.2-remark-click-selection-design.md)

## Global Constraints

- Enable mouse selection only while Remark Options is open.
- A click anywhere in an eligible Remarks module selects that translation.
- A textarea click retains native focus and caret behavior; do not call `preventDefault()` or move focus to `#rmd-edit`.
- A direct `input` event from an eligible NOVA Remarks textarea selects that translation if needed and mirrors its current value into `#rmd-edit`.
- Composer-originated synthetic input must remain a reverse-sync no-op when values already match.
- Use the existing `targetNumbers()` eligibility rules; empty translations stay excluded while populated translations exist.
- A successful click or direct edit consumes the one-shot first-ArrowUp jump.
- Switching targets reloads from the live target and must not copy text to another translation.
- Delegation must survive React-style replacement and duplicate nested wrappers with the same translation number.
- No changes to scoring, QC Compare, `TransCursor`, Submit Check, quote routing, or chip/settings behavior.
- No broad refactor or new file. A private helper is the only ease-of-development change.
- Closed-popover behavior and the initial-target rule remain unchanged.

## Review Focus

- A click on a nested non-textarea element inside a Remarks module must select its translation and preserve the clicked element's native focus.
- A direct edit to an ineligible empty translation must neither change the active target nor overwrite `#rmd-edit`.
- A selection made while `#rmd-edit` is focused must consume the first-ArrowUp jump, so the next ArrowUp does not unexpectedly return to Trans1.
- Replacing a Remarks textarea after selection must leave the next composer write and reverse sync attached to the same translation number.
- A click on the composer, a translation title, or a score control must not change the active Remarks target.

### Task 1: Click and direct-edit target synchronization

**Files:**
- Modify: `src/remark-composer.js`
- Test: `tests/remark-targets.spec.js`

**Interfaces:**
- Consumes: `cursor.set(n, { scroll = false, silent = false })`, `targetNumbers()`, `selectTarget(n, opts)`, `loadProxy()`, `Utils.transNumFromModuleName(mod, suffix)`, and `Utils.setNativeValue(textarea, text)`
- Produces: private `eventRemarkTarget(event) -> number | null`; accepted selections call `cursor.set(n)` and clear `jumpPending`

- [ ] **Step 1: Write the failing Playwright tests**

Add a `mouse selection and direct editing` describe block to `tests/remark-targets.spec.js`. Reuse `openComposer`, `expectTarget`, `expectRemarks`, `pageEdit`, and `edit`.

Cover these assertions:

- Click a non-textarea element inside `Trans4 Remarks` while Trans2 is active. Expect target `4`, `#rmd-edit` to load Trans4's existing text, and Trans2's value to remain unchanged.
- Click `Trans4 Remarks textarea`, place the caret at offset 2, and type one character. Expect target `4`, the typed value in both that textarea and `#rmd-edit`, and `document.activeElement` to remain the NOVA textarea.
- Dispatch an `input` event from an eligible textarea that is not active. Expect its translation to become active and its exact current value to appear in `#rmd-edit` without waiting for another click.
- Edit Trans3 while Trans1–2 and Trans4–7 remain populated. Expect the target and `#rmd-edit` to stay on the prior eligible translation, while Trans3 retains its page-side value.
- Click the same active Remarks module twice. Expect no target change and no text rewrite.
- Click `Trans4 Remarks` while focused in `#rmd-edit`, blur, then press ArrowUp. Expect sequential movement from Trans4, not the one-shot jump to Trans1.
- With the popover closed, click `Trans4 Remarks` and edit its textarea. Expect no `.rmd-active-target` and, after opening, the existing initial-target rule rather than retention of the closed click.
- Replace the active target's textarea, click the replacement, type through `#rmd-edit`, then edit the replacement directly. Expect both directions to stay on that translation number.
- Click `.rmd-title`, `#rmd-edit`, a translation title, and a score selector. Expect the active target to remain unchanged.

- [ ] **Step 2: Run the new tests and verify failure**

Run: `npx playwright test tests/remark-targets.spec.js -g "mouse selection and direct editing"`

Expected: FAIL because clicks do not select targets and direct edits only sync when the edited translation is already active.

- [ ] **Step 3: Implement the delegated selection path**

In `src/remark-composer.js`, add `eventRemarkTarget(event)`. It returns a translation number only when the event target has `closest`, its closest `[data-module-name]` parses with suffix ` Remarks`, and that number is included in `targetNumbers()`.

Change `onNovaRemarksInput(event)` so an eligible textarea first calls `cursor.set(eventRemarkTarget(event))` when it differs from `cursor.get()`, then mirrors `textarea.value` into `#rmd-edit` and the backdrop. Keep the existing same-value return so composer-originated writes do not loop.

Add a delegated `click` listener in `start()`, using capture phase. Ignore clicks while inactive, clicks inside `#rmd-popover`, and clicks without an eligible Remarks target. On an accepted target, set `jumpPending = false` and call `cursor.set(n)`. Do not prevent the event or move focus.

Apply the same `jumpPending = false` assignment on an accepted direct-edit target change, before calling `cursor.set(n)`.
