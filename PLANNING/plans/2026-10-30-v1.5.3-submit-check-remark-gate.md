# v1.5.3 Submit Check Remark Gate, Escape Unfocus, and Note Quotes Implementation Plan

> **Status:** Draft plan. Not approved for implementation. Based on the proposed spec `PLANNING/specs/2026-10-29-submit-check-non3-remarks-design.md` (`88b25c1`). Nothing here is implemented.

**Goal:** Hold Submit Check and Label Check when a populated non-3 translation has an empty Remarks field; let a selected remark textbox be blurred with Escape before the window closes; and let `Q` quote a selection taken from the left-hand Note module.

**Architecture:** All three changes stay in `src/remark-composer.js`. The remark-presence read is a small private helper that uses the existing `Utils.transNumFromModuleName` and `Utils.readSelected`. Population comes from `scoringShortcuts.checkCompleteness()`. Tests extend `tests/remark-targets.spec.js` and the reduced fixture `tests/fixtures/annotation.html`.

**Tech Stack:** Plain JavaScript userscript modules, Playwright tests, reduced annotation fixture.

## Reference Findings (from live DOM capture and code)

Checked against `NOVA Double Blind HTML example.txt` (outerHTML capture) and the two screenshots.

- **Note module:** `data-module-name="Note"`, `data-module-key="NoteTrans"`, `data-module-path` ends in `NoteTrans`. It is not a `TransN` module, so `Utils.transNumFromModuleName` returns `null` and `tryQuoteSelection` (`remark-composer.js:504`) refuses it today with "Selection must stay inside a single translation."
- **Remarks textareas:** each translation's Remarks is a `data-module-name="TransN Remarks"` module containing an `ant-input` textarea with placeholder `请输入...`. The observed spelling for Trans 2 is `"Trans 2 Remarks"` (with a space); the others are `"Trans1 Remarks"`. `Utils.transNumFromModuleName` already accepts an optional space, so the parser handles both. Tests must cover both.
- **Score modules:** `data-module-name="TransN Score"`. `Utils.readSelected(mod)` returns the displayed value, e.g. `3 Points` or `2 Points/Authenticity/Unauthentic Vocabulary / Collocations`.
- **Screenshot case:** in the Annotator 2 screenshot, Trans 2 scores `2 Points/...` with an empty `Trans 2 Remarks`. That is the exact case the gate must catch. Under current code it is not caught.
- **Escape:** `remark-composer.js:985` handles Escape before the `Utils.inTextEntry()` guard at `:990`, so an active composer exits on any Escape, including from a focused textbox.
- **Submit Check:** `performCheck` (`remark-composer.js:936`) blocks Enter on `incomplete` labels. The incomplete-label toast at `:944-948` is commented out (commit `c9c5444`).

## Global Constraints

- Gate logic reads only the live Remarks textarea value after trimming. It does not read the Remark Options proxy.
- A `3 Points` score (prefix match) never requires a remark.
- Empty translations are not gated. Population uses the same test as the label check.
- Check Off is unchanged. Empty-row auto-advance is unchanged and adds no new auto-submit case.
- Submit Check on pass still sends exactly one synthetic Space. On block, it sends none.
- Escape change: blur only `#rmd-edit` and NOVA per-translation Remarks textareas. Other text entry keeps the current behavior.
- Quoting Note never changes the selected remark target.
- No refactors, no new files beyond tests and plan/ledger docs, no scoring or QC Compare changes.
- Version: `v1.5.3` in the userscript header, README, and tests that check the version.

### Part 1: Z swaps Score and Remark together

- Z on a selected Trans on Annotator 1's tab applies Annotator 2's score **and** Annotator 2's remark for that translation as one action.

- A swapped Trans shows one badge covering both halves, for example `✓ Swapped to Annotator 2 · was: 3 Points + remark`, with a single Undo.
- Swap and Undo clicks on the badge (mouse) behave the same as Z.
- X, C, 3, 2 and the digit keys change the score only, as today. They never touch the remark.

### Part 5: Failsafe, preserved feedback and symmetric Z flip-flop

Goal: both annotators' feedback is never lost while you work, and Z always works as a flip-flop between Annotator 1's and Annotator 2's answers, even after either side's data has been cleared. Ownership does not matter: the pair is just two values, and you arbitrate which one stands.

- **Preserved pair.** On each row's first scrape, for every Trans N, store a pair `{ a: {score, remark}, b: {score, remark} }` (the two annotators' original values, read from each tab). The pair is the source of truth for Z. It lives in memory for the current row only and is cleared on a row change.
- **Never overwritten by a clear.** A re-scrape, the stale-text verify poll (`:739`), a tab switch, or the platform re-rendering a cleared field must not replace a stored non-empty value with an empty one. Clearing a score (X, the clear icon) or a remark on either tab changes only the live field, never the pair. The same goes for text hand-edited after the scrape.
- **Z is a symmetric flip-flop.** Z on the selected Trans decides which side the live value (score and remark, as a unit) currently matches:
  - matches `a` exactly: write `b`;
  - matches `b` exactly: write `a`;
  - matches neither (cleared, half-cleared, or hand-edited): write `b`, the next Z then writes `a`, and so on.
- **No "original owner" tracking.** The old `adopted` / `adoptedRemark` "was ..." maps are replaced by the pair. The badge's Undo means "flip back to the other side"; the badge position is unchanged.
- **Clears on either tab are survivable.** If Annotator 1's score or remark was cleared, Z restores it from the pair. If Annotator 2's was cleared on its tab, Z on Annotator 1's tab still writes Annotator 2's preserved value, because the pair, not the live Annotator 2 tab, is what Z reads.
- **Hand-edits are kept.** When Z is about to overwrite a live value that matches neither side, stash it in a per-Trans `manual` slot, shown as a `was:` line in the badge, so no typed work is destroyed (see Open Decision 8).
- **Still Annotator 1's tab only.** Z writes into Annotator 1's fields, as today. On Annotator 2's tab it keeps the "Switch to Annotator 1" refusal.
- **Auto-advance** applies to every Z that writes, flip-flop included; a Z that has nothing to write does not advance.

### Open Decisions (Track B)

1. **One key or two.** Recommended: one Z swaps Score and Remark together. A separate remark key is the alternative.
2. **Annotator 2's remark empty.** Recommended: clear Annotator 1's remark to match exactly, as a score swap overwrites. Alternative: leave Annotator 1's remark alone. The tests are written against the recommendation; flip them if you choose the alternative.
3. **Z after auto-advance.** Recommended: Z undoes only the currently selected Trans (press Up, then Z). Alternative: Z undoes the most recently swapped Trans from anywhere. The recommendation keeps Z predictable.
4. **Z when nothing differs.** Recommended: no write, no advance, and a one-line status "Trans N matches". Alternative: advance anyway so Z can be held down to walk the column. Say which you prefer.
5. **3-Points violation rule.** Recommended: replace the whole-row "Trans N" reference check with "scored 3 Points and has its own remark". Alternative: drop the warning.
6. **Where Annotator 2's remark is shown.** To swap a remark you can see it first. Recommended: the existing badge gains a second line `Remark: <Annotator 2's text>`, in place, so nothing moves. Alternative: show it only on hover.
7. **Whole-row Remarks.** Resolved: gone, delete its code.
8. **Hand-edited text when Z flips.** Recommended: stash the typed value in a per-Trans `manual` slot and show it in the badge, without adding it to the flip-flop. Alternative: make the flip-flop a three-way cycle `b`, `a`, `manual`.
9. **Originally empty values.** With the pair model, an annotator's originally empty remark is a real value, so Z can flip to it (clearing the field). Recommended for the score: keep the existing refusal when the other side has no score ("set it manually"), so Z never silently erases a score. This supersedes Decision 2: an empty remark flips like any other value.
