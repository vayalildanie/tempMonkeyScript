# v1.5.3 Submit Check Remark Gate, Escape Unfocus, and Note Quotes Implementation Plan

> **Status:** Draft plan. Not approved for implementation. Based on the proposed spec `PLANNING/specs/2026-10-29-submit-check-non3-remarks-design.md` (`88b25c1`). Nothing here is implemented.

**Goal:** Hold Submit Check and Label Check when a populated non-3 translation has an empty Remarks field; let a selected remark textbox be blurred with Escape before the window closes; and let `Q` quote a selection taken from the left-hand Note module.

**Architecture:** All three changes stay in `src/remark-composer.js`. The remark-presence read is a small private helper that uses the existing `Utils.transNumFromModuleName` and `Utils.readSelected`. Population comes from `scoringShortcuts.checkCompleteness()`. Tests extend `tests/remark-targets.spec.js` and the reduced fixture `tests/fixtures/annotation.html`.

**Tech Stack:** Plain JavaScript userscript modules, Playwright tests, reduced annotation fixture.

## Reference Findings (from live DOM capture and code)

Checked against `NOVA Double Blind HTML example.txt` (outerHTML capture) and the two screenshots.

- **Note module:** `data-module-name="Note"`, `data-module-key="NoteTrans"`, `data-module-path` ends in `NoteTrans`. It is not a `TransN` module, so `Utils.transNumFromModuleName` returns `null` and `tryQuoteSelection` (`remark-composer.js:504`) refuses it today with "Selection must stay inside a single translation."
- **Remarks textareas:** each translation's Remarks is a `data-module-name="TransN Remarks"` module containing an `ant-input` textarea with placeholder `请输入...`. The observed spelling for Trans 2 is `"Trans 2 Remarks"` (with a space); the others are `"Trans1 Remarks"`. `Utils.transNumFromModuleName` already accepts an optional space, so the parser handles both. Tests must cover both.
- **Score modules:** `data-module-name="TransN Score"`. `Utils.readSelected(mod)` returns the displayed value, e.g. `3 Points` or `2 Points/Authenticity/Unauthentic Vocabulary / Collocations`.
- **Screenshot case:** in the Annotator 2 screenshot, Trans 2 scores `2 Points/...` with an empty `Trans 2 Remarks`. That is the exact case the gate must catch. Under current code it is not caught.
- **Escape:** `remark-composer.js:985` handles Escape before the `Utils.inTextEntry()` guard at `:990`, so an active composer exits on any Escape, including from a focused textbox.
- **Submit Check:** `performCheck` (`remark-composer.js:936`) blocks Enter on `incomplete` labels. The incomplete-label toast at `:944-948` is commented out (commit `c9c5444`).

## Global Constraints

- Gate logic reads only the live Remarks textarea value after trimming. It does not read the Remark Options proxy.
- A `3 Points` score (prefix match) never requires a remark.
- Empty translations are not gated. Population uses the same test as the label check.
- Check Off is unchanged. Empty-row auto-advance is unchanged and adds no new auto-submit case.
- Submit Check on pass still sends exactly one synthetic Space. On block, it sends none.
- Escape change: blur only `#rmd-edit` and NOVA per-translation Remarks textareas. Other text entry keeps the current behavior.
- Quoting Note never changes the selected remark target.
- No refactors, no new files beyond tests and plan/ledger docs, no scoring or QC Compare changes.
- Version: `v1.5.3` in the userscript header, README, and tests that check the version.

## Open Decisions (resolve before Task 4)

1. **Blocked message vs silenced toast.** The spec asks the blocked message to name the translation and say whether the label or the remark is missing. Commit `c9c5444` deliberately commented out the incomplete-label toast. Options:
   - (a) Restore a toast for both missing label and missing remark. Reverses `c9c5444` for the label case.
   - (b) Keep the toast silenced and give the annotator a different signal, such as the hint line.
   - Recommendation: (a), with the copy distinguishing label from remark, since the spec requires it.
2. **Label Check gating.** The spec gates both Submit and Label Check. Confirm, since Label Check's untouched Enter otherwise submits through the page.
3. **Escape wording.** Confirm the first Escape only blurs and the second closes, as specified.

## Track B: QC Compare, Z Swaps Trans Score and Remarks

Track B changes `src/qc-compare.js` (the QC page, green "1" and red "3" tabs). It shares no code with Track A, which is annotation-stage `src/remark-composer.js`.

### Current Behavior (qc-compare.js)

- **Z on a selected Trans N** (`qc-compare.js:1407-1430`) calls `swap(n)` (`:950`), which runs `adoptOther(n)` (`:329`) or `undoAdopt(n)` (`:355`). Only the score moves. The `adopted` Map stores the prior score per translation.
- **Z on a Remark line** (`extraSel.type === 'remark'`) calls `appendRemarkLine` (`:662`). This appends a line of the whole-row `Remarks` field. It does not touch any per-translation remark.
- **Z on Rewrite** calls `adoptFieldText` / `undoFieldText`, the whole-field swap.
- **Scraping** reads per-translation text nowhere. `TEXT_FIELDS` (`:47-49`) holds only `remarks` (module `Remarks`) and `rewrite`. `Trans N Remarks` is never read on the QC page.
- **Test coverage:** no Playwright test references QC Compare. The fixture has no QC page.

### Evidence and Risk

- The reference capture (`NOVA Double Blind HTML example.txt`) is the annotation page. It has `data-module-name="TransN Remarks"` modules (including the spaced `Trans 2 Remarks`) and no plain `Remarks` module.
- The QC screenshots show per-translation Remarks textareas under each score, plus the row-level `备注` bar at top. The row-level bar is probably the `Remarks` module that QC reads today.
- **Unverified:** the QC page's per-translation remark modules and their attributes. Confirm from a QC outerHTML capture of both annotator tabs before Task B1.

### Proposed Behavior

- **Z on a selected Trans N** on Annotator 1's tab swaps the score and `Trans N Remarks` to Annotator 2's values as one action.
- A Trans whose score matches but whose remark differs still acts on Z, and only the remark is swapped.
- The remark swap replaces the whole text, as the score swap does. It is not a line append.
- A second Z on that Trans restores both score and remark to the values captured on the first Z.
- Coupling is the reason for one key. A 3-Points Trans must not carry a remark, and swapping only one half could create a mismatch that `get3PtRemarkViolations` then flags.
- Z on a Remark line or Rewrite is unchanged.
- The Z-key hint at `qc-compare.js:1249` changes to name Scores and Remarks.

### Open Decisions (Track B)

1. **One key or two.** Recommendation: one Z swaps score and remark together. The alternative is a separate remark key.
2. **Annotator 2 remark empty.** Recommendation: clear Annotator 1's remark to match exactly, consistent with a score swap. The alternative is to leave Annotator 1's remark alone when Annotator 2's is empty.
3. **Annotator 2 score empty.** Keep the existing refusal ("set it manually"). Confirm the remark swap does not run in that case either.
4. **Release.** Decided: ship Track B in the same v1.5.3 release as Track A. Track B's files and tests stay separate, so it can still be split out later if needed.
