# v1.5.5 Window Polish and Tech-Debt Pass Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stop QC Compare's endless idle re-render, make Remark Options' window controls stay on-screen and resize sanely, and clear the specific tech-debt items (duplicated helpers, a missing panel-geometry fix, quote/separator cleanup, coverage gaps) identified across two audit passes — without changing any key binding's physical key, scoring flow, Submit Check rules, or QC's Z semantics.

**Architecture:** No new files, no build step, no new dependency. Everything lands in the existing five `src/*.js` Tampermonkey `@require` modules (`utils.js`, `trans-cursor.js`, `scoring-shortcuts.js`, `remark-composer.js`, `qc-compare.js`) plus `tests/`. Shared mechanism moves into `utils.js`; each module keeps its own state and storage keys. One task = one commit on `release/v1.5.5`, tests-first, in the order below.

**Tech Stack:** Vanilla JS (Tampermonkey userscript), Playwright for tests (`@playwright/test` — the only dependency), no React/build tooling in this repo (the page under test is NOVA's own React app; this script only reads/writes its DOM).

**Spec:** `PLANNING/specs/2026-10-31-v1.5.5-window-polish-and-tech-debt-design.md` (sections 1–7) plus `PLANNING/plans/2026-10-31-v1.5.5-window-polish-and-tech-debt.md` (the prior prose plan this document supersedes with per-step TDD detail). Both travel with this plan — read the spec's requirement IDs (`W-`, `P-`, `C-`, `T-COV`) and tech-debt IDs (`D1`–`D22`) referenced in each task below.

**Note on two corrected findings.** Re-reading the actual code while writing this plan (not just the spec) turned up two places where the spec's stated root cause doesn't match what's in `src/` today:

1. **D1 (QC idle loop)** — the spec blames `renderBadges` rewriting badge `innerHTML` unconditionally. That write is **already guarded** (`qc-compare.js:655`, `if (badge.innerHTML !== html) badge.innerHTML = html;`, present since v1.4.0). The actual unconditional write is `setSummary`/`updateSummary` (`qc-compare.js:724` and `:746-753`), called at the end of every `renderBadges()` — that's the real idle-loop source. Task 2 below targets that, not badge rendering.
2. **C-PANELFIT (D12)** — the spec frames the QC-panel fix as "generalize `fitPopover` into `Utils.fitIntoView`." QC Compare has no saved *size* at all (only position — it's not resizable), so the only thing missing is the position clamp Scoring Shortcuts already gets from the already-shared `Utils.clampIntoView` (`utils.js:167`). No new `Utils` function is needed; Task 10 just wires the existing one in.

## Review Focus

1. **WASD pressed while focus is on a non-text interactive control** (an open Ant cascader/select menu, a button) rather than a `textarea`/`input`. `Utils.inTextEntry()` only recognizes text-entry elements, so a native dropdown's own letter-key behavior (if any) is not shielded the way arrows already coexist with it. Reasonable expectation: WASD behaves exactly like the matching arrow in every state arrows are already tested in, including with a label-pick cascader menu open. → test added in Task 18.
2. **A selection containing a literal `"` character**, quoted with Q (V6: left as-is). Reasonable expectation: the remark box ends up with the literal, unescaped text and nothing crashes or corrupts a later join. → test added in Task 7.
3. **The duplicate-quote guard (Task 7) over-matching a different, merely similar selection.** Quoting "cat" then quoting "cats" right after are two different quotes; a implementer could write the guard as a substring/prefix check instead of an exact trailing match. Reasonable expectation: only an *exact* repeat is blocked. → test added in Task 7.
4. **Typing inside the Settings rename field while a NOVA row-change mutation fires**, once Task 3's shared `observeSettled` is in place. `#rmd-settings-overlay` must be in the own-UI filter or every keystroke there would be treated as "the page changed" and could reset state mid-edit. Reasonable expectation: editing a chip group name never triggers a row-change reset. → test added in Task 3.
5. **QC Compare's panel-fit (Task 10) touching size when QC has none.** QC never had a saved size (no resize handle), only position. Reasonable expectation: the fix clamps `left`/`top` only and never sets an inline `width`/`height` on QC's panel. → test added in Task 10.
