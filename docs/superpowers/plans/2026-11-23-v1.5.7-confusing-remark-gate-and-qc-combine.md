# v1.5.7 — Confusing remark gate + QC Compare `V` (combine remarks) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Self-explanatory Confusing sub-labels stop blocking Submit Check (and auto-submit when clean), and QC Compare gets a reversible `V` key that merges both annotators' remarks while keeping the label currently selected.

**Architecture:** One shared predicate `Utils.needsRemark(scoreText)` becomes the single source of truth for "does this label need a remark", replacing two divergent rules (the submit gate's "anything not 3 Points" and the composer's "Likely need remarks" list). QC `V` writes a combined remark into the live Remarks box only, and records the result on the existing preserved `pairs` entry so `Z` can always restore Annotator 1's original; the originals are never mutated.

**Tech Stack:** Plain-JS Tampermonkey modules under `src/` (no build step), Playwright suite (`npm test`) against the simulated pages in `tests/fixtures/`.

**Spec:** `docs/superpowers/specs/2026-11-17-confusing-subcategory-labels-design.md` (the Confusing tree and the "only `Other / open feedback` needs a remark" rule it fixed for the composer). The v1.5.7 requests are restated in "Decisions" below; no separate design doc.

## Global Constraints

- Production files stay plain JavaScript, no build step, `@grant none`.
- Modules stay behaviorally isolated (README "Ground rules"): shared *stateless* code goes in `src/utils.js`; `qc-compare.js` keeps its own copies of platform strings.
- Exact label string needing a remark: `Confusing / Other / open feedback` (exact full-string match, never split on `/` — the label itself contains one).
- `2 Points …` and `Confusing / Other / open feedback` need a remark; `3 Points` and every other `Confusing / …` leaf do not. Bare `2 Points` / bare `Confusing` stay "incomplete label" and still block (`isLabelComplete`, untouched).
- QC writes only on the Annotator 1 tab, never while `scraping`/`adopting`, never while the row signature differs from `lastRowSig` (same guards as `flip`).
- The preserved pair (`pairs.get(n).a` / `.b`) is never mutated by any write.
- Version `1.5.7` in: `annotation-scoring-shortcuts.user.js` (`@version`, `TL.SCRIPT_VERSION`, header note), `README.md`, `tests/release-smoke.spec.js` (`VERSION`).

## Decisions (interpretations to confirm on review)

1. **Which Confusing labels skip the remark:** all `Confusing / …` leaves except `Other / open feedback` — the same set the composer already treats as self-explanatory. The gate uses an *exempt* list (3 Points, Confusing-except-Other) rather than a *required* list, so a label NOVA adds later still blocks by default (fail-safe) until it is added to the exempt rule.
2. **`V` result:** live remark becomes `A.remark.trim() + "; " + B.remark.trim()` (originals, not the live text); empty or identical sides collapse to the single non-empty text. Score is whatever is live now (the label "currently selected"). Separator is one constant (`CFG.combineJoin`).
3. **Reversal:** `Z` on a combined translation returns Annotator 1's original unit directly. `X` then `Z` also works: after `X` clears the score, the remark still equals the combined text, so `Z` recognises it and restores `A` (not `B`). `X` advances the cursor as today, so step back (`ArrowUp`/`W`) before `Z`, exactly like the existing X→Z tests.
4. **`V` advances** to the next translation on success, like every writing `Z`/`X`.
5. A combined translation counts as reconciled in the QC summary (the reviewer made the call); it is not counted as "swapped".
6. **Out of scope (deferred):** a mouse button for combine; splitting the submit-check system out of `remark-composer.js` into its own file (valuable for maintenance — 1,168 lines — but a move-only refactor that deserves its own release); sharing path-key strings across modules (intentional per ground rules).

## Review Focus

- Whitespace-only remark on one side (`'  '` + `'x'`) → result is `x`, no stray `; `. (Task 2)
- `V` pressed while a Remarks box has focus types the letter and does not combine. (Task 2)
- Two rapid `V` presses write once (in-flight guard) and a second `V` on an already-combined translation refuses with a message instead of re-writing. (Task 2)
- A hand-edited live remark is not lost when `V` overwrites it (kept in `pair.manual`, shown in the badge like `Z` does). (Task 2)
- A new/unknown Confusing leaf is exempt by rule, so `Other / open feedback` is the only guard — the parity test enumerates every fixture leaf so a mistaken edit to the constant fails loudly. (Task 1)
